## 1. 용어 3분 정리

| 말         | 뜻                                                                 |
| ---------- | ------------------------------------------------------------------ |
| **저장소** | 프로젝트 폴더 하나. GitHub에 올라가 있는 것 = 원격 저장소          |
| **커밋**   | "여기까지 저장!" 하고 찍는 도장. 나중에 이 시점으로 돌아올 수 있음 |
| **브랜치** | 평행세계. 내 브랜치에서 마음대로 해도 `main`은 안전함              |
| **`main`** | 진짜 최종본이 있는 브랜치. **여기서 직접 작업하면 안 됨**          |
| **`dev`**  | 다 같이 작업물을 모으는 곳. **여기도 직접 작업 금지**              |
| **푸시**   | 내 컴퓨터의 커밋을 GitHub에 올리기                                 |
| **풀**     | GitHub의 최신 코드를 내 컴퓨터로 가져오기                          |
| **PR**     | "제 작업 확인하고 `dev`에 합쳐주세요" 하는 요청서                  |
| **머지**   | PR을 승인해서 실제로 합치는 것                                     |
| **충돌**   | 나와 팀원이 같은 줄을 다르게 고쳐서 컴퓨터가 못 고르는 상황        |

## 2. 왜 브랜치를 만들어야 하나요?

5명이 같은 브랜치에서 동시에 작업하면 이런 일이 생깁니다.

```
내가 저장 → 친구가 저장 → 내 코드가 사라짐 😱
```

브랜치를 쓰면 각자 다른 평행세계에서 일합니다.

```
main ────────────────────────────●──────  최종본 (가끔만 합침)
                                /
dev  ──●──────●──────●─────────●───────  다 같이 모으는 곳
        \      \      \
         ●──●   ●──●   ●──●              각자의 작업 브랜치
      feat/login  fix/header  chore/...
```

우리 팀의 규칙은 이렇습니다.

1. 작업할 땐 **`dev` 에서 새 브랜치를 판다** (`main` 아님!)
2. 다 하면 **`dev` 로 PR** 을 올린다
3. 기능이 어느 정도 모이면 **`dev` → `main`** 으로 한 번에 합친다 (선생님/팀장이 함)

**규칙: 코드를 한 글자라도 고치기 전에 브랜치부터 만든다.**

`main` 과 `dev` 에서는 커밋 자체가 **자동으로 막힙니다.** 막혔다면 브랜치를 안 만든 겁니다.

## 3. 매일 쓰는 흐름 (이것만 알면 됩니다)

Claude Code 를 쓴다면 왼쪽 명령어 하나면 끝납니다.

| 하고 싶은 것        | Claude Code                 | 직접 친다면                                                                |
| ------------------- | --------------------------- | -------------------------------------------------------------------------- |
| 새 작업 시작        | `/start 로그인 화면 만들기` | `git switch dev` → `git pull origin dev` → `git switch -c feat/login-page` |
| 지금까지 한 것 저장 | `/save`                     | `git add <파일>` → `git commit -m "..."`                                   |
| GitHub에 올리고 PR  | `/pr`                       | `git push` → GitHub에서 PR 버튼                                            |
| 팀원 코드 가져오기  | `/sync`                     | `git pull origin dev`                                                      |
| 검사 돌리기         | `/check`                    | `pnpm run typecheck lint build`                                            |
| 개발 서버 켜기      | `/run`                      | `pnpm run dev`                                                             |
| 에러가 났을 때      | `/fix <에러 내용>`          | 😭                                                                         |

## 4. 하루 작업 순서 (실제 예시)

```
아침
  1. /sync              ← 어제 팀원들이 올린 코드 받아오기
  2. /start 할 일 목록 화면 만들기
     → "브랜치 이름 골라주세요" 라고 물어봅니다. 고르면 끝.

작업하면서
  3. Claude에게 시킨다:  "할 일을 추가하는 입력창이랑 버튼 만들어줘"
  4. /run 으로 브라우저에서 확인
  5. 어느 정도 됐다 싶으면  /save      ← 커밋 메시지는 알아서 써줍니다
  6. 3~5 반복

끝나면
  7. /pr                ← PR 링크가 나옵니다
  8. 팀원에게 "검토 부탁해" 하고 링크 전달
  9. 팀원이 승인하면 GitHub 웹에서 Merge 버튼 클릭
 10. /sync 로 합쳐진 dev 다시 받아오기

※ dev 에 모인 것을 main 으로 올리는 건 선생님/팀장이 따로 합니다.
```

## 5. 자주 하는 실수와 해결

### 😰 "main(또는 dev) 브랜치에서 작업해버렸어요"

아직 커밋 안 했다면 그대로 브랜치만 만들면 됩니다. 작업물은 따라옵니다.

```bash
git switch -c feat/작업이름
```

Claude에게 "지금 main에서 작업했는데 브랜치로 옮겨줘" 라고 해도 됩니다.

### 😰 "실수로 파일을 지웠어요"

커밋한 적이 있다면 되살릴 수 있습니다.

```bash
git checkout -- <파일경로>
```

### 😰 "충돌(conflict)이 났어요"

`<<<<<<<`, `=======`, `>>>>>>>` 같은 기호가 파일에 생깁니다.
**혼자 지우지 마세요.** Claude에게 이렇게 말하세요.

> 충돌 났어. 어떤 파일이 왜 충돌했는지 설명해주고 어떻게 할지 물어봐줘.

### 😰 "커밋 메시지를 잘못 썼어요"

아직 푸시 안 했다면 고칠 수 있지만, **이미 푸시했다면 그냥 두세요.**
다음 커밋부터 잘 쓰면 됩니다. 억지로 고치다가 더 큰 사고가 납니다.

### 😰 "뭐가 뭔지 모르겠어요"

```bash
git status
```

이거 하나면 지금 어느 브랜치에 있고 뭐가 저장 안 됐는지 다 나옵니다.
Claude에게 `git status 결과 해석해줘` 라고 해도 됩니다.

## 6. 절대 하면 안 되는 것

| 금지                        | 왜                                    |
| --------------------------- | ------------------------------------- |
| `git push --force`          | 팀원이 올린 작업이 통째로 사라집니다  |
| `git reset --hard`          | 저장 안 한 작업이 영원히 사라집니다   |
| `main` / `dev` 에 직접 push | 검토 없이 공용 코드가 바뀝니다        |
| `.env` 파일 커밋            | 비밀번호·API 키가 인터넷에 공개됩니다 |
| 남의 브랜치 삭제            | 그 사람 작업이 날아갑니다             |

앞의 네 개는 **이 프로젝트에서 자동으로 차단**해 두었습니다. (`.claude/hooks/guard-git.sh`)
정말 필요하면 선생님이나 팀장에게 먼저 물어보세요.
