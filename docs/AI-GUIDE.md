# Claude Code 사용법

코딩이 처음이어도 이 프로젝트를 할 수 있게 만들어 둔 도구들입니다.

---

## 1. 시작하기

프로젝트 폴더에서:

```bash
claude
```

처음 실행하면 **"이 프로젝트의 MCP 서버를 사용할까요?"** 라고 물어봅니다 → **예**

---

## 2. 슬래시 명령어

`/` 를 치면 목록이 뜹니다.

| 명령                        | 하는 일                                                |
| --------------------------- | ------------------------------------------------------ |
| `/setup`                    | 최초 세팅 — 준비물 확인 + MCP 연결                     |
| `/start 로그인 화면 만들기` | **브랜치 이름 후보를 주고** 골라서 브랜치 생성 후 작업 |
| `/save`                     | 검사 4종 + **커밋 메시지 자동 작성**                   |
| `/pr`                       | 푸시 + PR 생성 (**체크리스트 직접 검증해서 채움**)     |
| `/check`                    | 검사 4종을 한 번에                                     |
| `/sync`                     | 팀원이 올린 최신 코드 가져오기                         |
| `/run`                      | 개발 서버 켜기                                         |
| `/fix <에러 메시지>`        | 에러 뜻 설명 + 같이 고치기                             |

---

## 3. 스킬 — 알아서 켜지는 지침

명령어를 치지 않아도, 상황에 맞는 스킬이 **자동으로** 적용됩니다.

| 스킬            | 언제 켜지나                                 |
| --------------- | ------------------------------------------- |
| `github-flow`   | 커밋·브랜치·푸시·PR 관련 작업               |
| `new-page`      | "~~ 페이지 만들어줘" — 라우터 연결까지 자동 |
| `new-component` | "버튼 만들어줘", "이거 재사용하게 빼줘"     |
| `responsive-ui` | 화면·레이아웃·"모바일에서 깨져요"           |

즉 `"할 일 목록 페이지 만들어줘"` 라고만 해도
파일 생성 → 라우터 등록 → 헤더 메뉴 추가 → 반응형 적용까지 순서대로 해줍니다.

## 4. 안전장치 — 3겹으로 막습니다

각 층이 막는 범위가 다릅니다. 하나로는 부족해서 겹쳐 놓았습니다.

| 층                   | 언제 작동                      | 막는 범위                     | 뚫리는 경우                |
| -------------------- | ------------------------------ | ----------------------------- | -------------------------- |
| ① Claude Code 훅     | **Claude 가** 명령을 실행할 때 | 거의 모든 위험 명령 (아래 표) | 학생이 터미널에 직접 칠 때 |
| ② husky (git 훅)     | **누가 치든** 커밋·푸시할 때   | 커밋·푸시 관련만              | `--no-verify`, `HUSKY=0`   |
| ③ GitHub 브랜치 보호 | 서버에서                       | main·dev 로의 푸시            | (못 뚫음 — 진짜 방어선)    |

### ① Claude Code 훅 (`.claude/hooks/guard-git.sh`)

Claude 가 실행하는 모든 Bash 명령을 검사합니다.

| 막히는 것                                 | 왜                                    |
| ----------------------------------------- | ------------------------------------- |
| `main` / `dev` 에 직접 커밋·푸시          | 검토 없이 공용 코드가 바뀜            |
| `push --force` / `-f` / `origin +main`    | 원격 커밋을 덮어써 팀원 작업이 사라짐 |
| `push --mirror`                           | 내게 없는 원격 브랜치를 **전부 삭제** |
| `push --delete` / `-d` / `origin :브랜치` | 원격 브랜치가 사라짐                  |
| `push --prune`                            | 원격 브랜치가 무더기로 사라짐         |
| `reset --hard`                            | 저장 안 한 작업이 영원히 사라짐       |
| `clean -f` / `-fd` / `-fdx`               | 새로 만든 파일이 전부 삭제됨          |
| `checkout .` / `restore .`                | 저장 안 한 수정을 전부 버림           |
| `stash clear` / `stash drop`              | 치워둔 작업이 영구 삭제됨             |
| `filter-branch` / `filter-repo`           | 모든 커밋을 다시 써서 팀원과 어긋남   |
| `reflog expire` / `gc --prune`            | 마지막 복구 수단이 사라짐             |
| `update-ref -d` / `branch -d` / `-D`      | 브랜치가 기록 없이 사라짐             |
| `remote remove` / `set-url`               | 엉뚱한 저장소로 푸시됨                |
| `rm -rf .git`                             | 모든 커밋 기록이 사라짐               |

평소 쓰는 명령은 그대로 통과합니다.
`git push -u origin feat/x`, `git stash pop`, `git checkout -- 파일`, `git clean -n` 등.

### ② husky (`.husky/`)

터미널에 **직접** 쳐도 막힙니다. `pnpm install` 할 때 자동으로 설치됩니다.

| 훅           | 하는 일                                                           |
| ------------ | ----------------------------------------------------------------- |
| `pre-commit` | main·dev 직접 커밋 차단 + 커밋할 파일만 Prettier·oxlint 자동 실행 |
| `commit-msg` | 커밋 메시지가 `타입: 한국어 설명` 형식인지 검사                   |
| `pre-push`   | main·dev 직접 푸시, **강제 푸시**, 브랜치 삭제 푸시 차단          |

강제 푸시 판별 방법: git 은 `--force` 를 썼는지 알려주지 않습니다.
대신 **원격 커밋이 내 커밋의 조상이 아니면** 원격 기록을 덮어쓰는 것이므로 강제 푸시로 봅니다.
`--force`, `--force-with-lease`, `-f`, `origin +main`, `--mirror` 가 전부 여기에 걸립니다.

> ⚠️ `--no-verify` 를 붙이면 husky 는 통째로 건너뛰어집니다. 절대 쓰지 마세요.
> 이건 "내가 지금 뭘 하는지 정확히 안다" 는 뜻인데, 대부분은 그렇지 않습니다.

### ③ GitHub 브랜치 보호

①②는 **내 컴퓨터 안에서만** 작동합니다. `.claude/` 나 `.husky/` 를 지우면 무력화됩니다.
`main` 과 `dev` 를 진짜로 지키려면 GitHub 저장소 설정에서 브랜치 보호를 켜야 합니다.
이건 선생님/팀장이 웹에서 한 번 설정합니다.

## 5. MCP — 외부 서비스 연결

MCP 는 Claude 가 GitHub·Vercel 같은 서비스를 **직접 다루게** 해주는 연결 통로입니다.

이 저장소에는 `.mcp.json` 이 들어 있어서 따로 설치할 필요가 없습니다.
`claude` 실행 시 "사용할까요?" 에 **예**를 누르면 됩니다.

| 이름     | 주소                                 | 뭘 할 수 있나                  |
| -------- | ------------------------------------ | ------------------------------ |
| `github` | `https://api.githubcopilot.com/mcp/` | 이슈·PR 읽고 만들기, 코드 검색 |
| `vercel` | `https://mcp.vercel.com`             | 배포 상태 확인, 실패 로그 보기 |

### 연결 확인 / 로그인

```
/mcp
```

- 목록에 없으면 → Claude Code 를 껐다 켜고 다시 `/mcp`
- 로그인이 안 됐으면 → 해당 서버를 골라 **Authenticate** → 브라우저에서 승인

### ⚠️ MCP 보안

- MCP 를 연결하면 그 서비스에서 **내 계정 권한 그대로** 동작합니다.
- 공식 주소가 맞는지 꼭 확인하세요. 비슷한 가짜 주소가 있을 수 있습니다.
- **출처를 모르는 MCP 서버는 붙이지 마세요.**
- MCP 없이도 이 프로젝트는 전부 동작합니다. 안 되면 GitHub 웹을 쓰면 됩니다.

## 6. 질문 잘 하는 법

AI에게 시킬 때도 요령이 있습니다.

| ❌ 이렇게 말고  | ✅ 이렇게                                                           |
| --------------- | ------------------------------------------------------------------- |
| "안 돼요"       | "버튼을 눌렀는데 아무 일도 안 일어나요. 콘솔에 이 에러가 떠요: ..." |
| "예쁘게 해줘"   | "카드 사이 간격을 넓히고 모서리를 둥글게 해줘"                      |
| "다 만들어줘"   | "먼저 할 일 목록을 보여주는 화면만 만들어줘"                        |
| "이거 왜 이래?" | "이 코드가 왜 이렇게 동작하는지 설명해줘. 고치진 말고."             |

**한 번에 하나씩** 시키는 게 훨씬 빠릅니다.

## 7. AI가 준 코드를 그대로 믿지 마세요

- **이해 안 되는 코드는 "왜 이렇게 했는지 설명해줘" 라고 물어보세요.**
  설명을 못 하면 그 코드는 쓰지 않는 게 낫습니다.
- 화면은 **직접 브라우저에서 확인**하세요. PC와 모바일 둘 다.
- AI도 틀립니다. `/check` 가 통과했다고 해서 원하는 대로 동작한다는 뜻은 아닙니다.

> 이 프로젝트의 목적은 "AI가 만든 결과물"이 아니라
> **여러분이 만들고 설명할 수 있는 결과물**입니다.
