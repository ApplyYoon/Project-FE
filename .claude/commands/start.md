사용자가 새 작업을 시작합니다. 하고 싶은 일: **$ARGUMENTS**

## 1. 지금 상태 확인

```bash
git symbolic-ref --short -q HEAD && git status --short
```

- 커밋 안 된 수정이 있으면 **멈추고** 물어봅니다.
  > "저장 안 된 작업이 N개 있어요. `/save` 로 먼저 저장할까요, 아니면 그대로 새 브랜치로 가져갈까요?"

## 2. 브랜치 이름 후보를 **만들어서 물어본다**

사용자는 영어 이름을 짓기 어려워합니다. **당신이 후보를 3개 만들어서 고르게 하세요.**
그냥 하나 정하고 넘어가는 것도, "브랜치 이름 뭐로 할까요?" 라고 빈손으로 묻는 것도 안 됩니다.

### 이름 규칙

```
타입/영문-설명            feat/login-form
타입/이슈번호-영문-설명   feat/12-login-form     ← 이슈 번호를 알면 이 형태
```

소문자 + 하이픈만. 한글·공백·대문자·언더바 금지. 2~4단어가 적당합니다.

### 타입 고르기

| 사용자가 이렇게 말하면                       | 타입       |
| -------------------------------------------- | ---------- |
| 만들어줘 / 추가해줘 / 새로                   | `feat`     |
| 안 돼요 / 이상해요 / 깨져요 / 고쳐줘         | `fix`      |
| 정리해줘 / 깔끔하게 / 나눠줘 (동작은 그대로) | `refactor` |
| 색 / 간격 / 폰트 / 예쁘게 (보이는 것만)      | `style`    |
| README / 문서 / 설명                         | `docs`     |
| 패키지 / 설정 / 버전                         | `chore`    |

### 자주 쓰는 한국어 → 영어

| 한국어    | 영어        | 한국어    | 영어         |
| --------- | ----------- | --------- | ------------ |
| 로그인    | `login`     | 회원가입  | `signup`     |
| 할 일     | `todo`      | 게시판    | `board`      |
| 글/게시글 | `post`      | 댓글      | `comment`    |
| 검색      | `search`    | 상세      | `detail`     |
| 목록      | `list`      | 프로필    | `profile`    |
| 헤더/상단 | `header`    | 메뉴      | `nav`        |
| 장바구니  | `cart`      | 지도      | `map`        |
| 달력      | `calendar`  | 알림      | `alert`      |
| 다크모드  | `dark-mode` | 반응형    | `responsive` |
| 버튼      | `button`    | 모달/팝업 | `modal`      |

### 후보 만드는 요령

후보 3개는 **서로 다른 각도**로 만듭니다. 비슷한 걸 3개 내놓지 마세요.

- 예: "로그인 화면 만들래"
  1. `feat/login-page` — 화면 단위로 본 이름
  2. `feat/login-form` — 폼(입력창) 중심으로 본 이름
  3. `feat/auth-ui` — 인증 기능 전체로 본 이름

- 예: "헤더가 모바일에서 깨져요"
  1. `fix/header-mobile-layout`
  2. `fix/header-overflow`
  3. `fix/responsive-header`

`AskUserQuestion` 으로 물어보세요. (사용자가 직접 입력할 수도 있습니다)

> **이번 작업 브랜치 이름을 골라주세요**
>
> 1. `feat/login-page` — 로그인 화면 전체를 만드는 작업
> 2. `feat/login-form` — 입력 폼에 집중한 이름
> 3. `feat/auth-ui` — 로그인·회원가입을 함께 다룰 예정이면

이슈 번호를 이미 알고 있다면 후보에 번호를 넣어 제시하세요. (`feat/12-login-page`)

## 3. 최신 dev 에서 브랜치 만들기

작업 브랜치는 **`main` 이 아니라 `dev` 에서** 땁니다.
(브랜치 전략: `작업 브랜치 → dev → main`)

```bash
git switch dev
git pull origin dev
git switch -c <고른-이름>
```

`dev` 가 없다는 에러가 나면 원격에서 받아옵니다.

```bash
git fetch origin && git switch -c dev origin/dev
```

그래도 없으면 아직 dev 가 안 만들어진 것입니다. 사용자에게 알리고,
허락을 받은 뒤 `main` 에서 dev 를 만드세요. (`git switch -c dev main`)

`git pull` 이 실패해도(인터넷/권한) 그대로 진행하되 사용자에게 알려주세요.

## 4. 짧게 보고하고 바로 작업 시작

> `feat/login-page` 브랜치를 만들었어요. 이제 작업 시작할게요.
> 다 되면 `/save` 로 저장하고, `/pr` 로 올리면 됩니다.

그리고 **$ARGUMENTS 작업을 바로 이어서 진행하세요.** 여기서 멈추지 마세요.

작업할 때는 `responsive-ui` 스킬의 규칙(모바일 먼저 → `sm:` 로 키우기)을 지키고,
새 페이지라면 `new-page` 스킬을 따릅니다.
